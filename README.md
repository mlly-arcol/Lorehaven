# NativeTavern

NativeTavern 是一款面向个人使用的 Windows 原生 AI 角色聊天客户端。它使用 WPF 构建，不依赖浏览器或 Node.js，支持在线 API、本地模型、角色卡、世界书、Persona、提示词预设、知识库、多角色群聊和插件包管理。

当前版本：**2.2.0**

[下载最新版本](https://github.com/mlly-arcol/NativeTavern/releases/latest)

## 主要功能

### 角色与分组

- 创建、编辑、删除和收藏角色
- 按名称、标签或描述搜索角色
- 为角色填写别名（逗号分隔，中英文逗号都可以），搜索时别名与名称同样命中
- 为角色设置本地头像
- 导入 PNG Character Card V2/V3 和 JSON 角色卡，也可导出为 PNG 图片角色卡或 JSON
- 使用角色卡中的 Description、Personality、Scenario、First Message 和 Example Messages
- 创建、重命名和删除角色分组
- 通过复选框调整分组成员
- 折叠或展开分组；已分组角色不再重复出现在未分组列表
- 删除分组只会解除角色归属，不会删除角色

每个角色最多属于一个角色分组。

### 单角色聊天

- 为指定角色创建独立会话
- 流式显示模型回复，可随时停止生成
- 回复还在生成时可以继续输入并发送，这条消息会进入“⏳ 排队待发送”，等本轮回复结束后自动发出；每条可单独 ✕ 取消，也可一键清空
- 排队按对话分别保存：切到别的对话不会替它发送，切回来时才补发
- 编辑、复制和删除单条消息
- 重新生成助手回复
- 助手回复停在半路时点“续写”，让角色接着最后那句往下写；原文保持不变，新版本作为额外候选存下，仍可向左翻回较短的版本
- 保存并左右切换多个候选回复（Swipe）
- 可在任意消息处创建独立聊天分支，并从分支返回源对话
- 可直接重命名当前对话
- 顶部的 📌 按钮置顶或取消置顶当前对话；置顶只改一个标记，不会改动“最近更新时间”排序
- 在“⚙ 对话设置”里可为对话填写分组名（留空即取消分组），分组会跟着标题显示在切换下拉里，下拉列表也会自动收集已有分组
- 切换或删除历史会话
- 每个对话各自记住没发出去的输入（包括待发送的图片），切换对话会自动带走各自的草稿，关闭程序再打开也还在；发送成功或删除对话后该草稿即清空
- 长对话加载需要几秒，加载中新敲进去的内容优先保留，不会被切换前的草稿覆盖
- 打开对话时按整段批量读取候选回复与图片附件，几百条消息的历史也只需几次数据库往返
- 草稿在停止输入约 0.8 秒后才写盘（不是每次按键），切换对话、发送、删除时立即写入
- First Message 自动作为角色的首条消息显示
- 首段生成前显示“正在思考”呼吸动画，回答按完整自然段渐进呈现
- 每次角色回复后，根据当前剧情生成 3 条可编辑、可选择的用户回复建议
- 长会话达到 20 条消息后自动整理“剧情回顾”，只覆盖较早的轮次，最近消息原样保留
- 聊天页顶部的 ❖ 打开剧情回顾面板：可查看、直接改写并保存（保存后自动整理暂停），也可一键重新生成或清空
- 自动整理是增量的：每次只读还没覆盖的新消息，不再每轮回复都重算整段历史；回顾过长时优先丢弃最早的条目而不是最新的情节
- 在聊天页顶部输入关键词并按回车，可跨所有对话搜索消息内容；点击结果直接进入对应对话并滚动到该条消息
- 搜索结果只展示命中位置附近的内容摘要，最多返回 30 条
- 搜索词前加 `@角色名` 或 `@别名` 只查该角色说过的内容，例如 `@守墓人 碑`；@ 之后不写关键词则列出该角色全部发言
- 多人对话在标题下方按发言者生成筛选按钮，点击只看某个角色的消息，点“全部”恢复；从搜索或收藏列表跳转时会自动放开筛选
- 顶部的 📊 打开对话统计：消息数、字数（我 / 角色）、平均角色回复字数、候选回复、收藏与图片数量、对话时间跨度，多人对话还会按字数给出各角色发言占比，并列出角色反复用到的口头禅
- 统计里的字数按非空白字符计，中文按“字”统计，不受标点和空格影响
- 📊 面板还会列出“角色反复用到的说法”：统计最近 120 条角色回复里出现 3 次以上的短语（标点在内也认），用来抓模型的口头禅；同一个说法只按最长的形式显示一次
- 每条消息旁的 ☆ 按钮可收藏该消息，再点一次取消收藏；收藏不会改动消息时间、正文和候选回复
- 顶部的 ★ 按钮打开当前对话的收藏列表，点击条目直接滚动到那条消息
- 导出时收藏的消息会在 Markdown 标题上标注 `★ pinned`，JSON 中带 `pinned` 字段
- 角色记忆（🧠）：在设置中启用后，每若干轮对话自动提炼一次角色该长期记住的要点——关于用户的稳定事实和对后续剧情有持续影响的变化；记忆跟着角色走，跨对话保留，可在聊天页顶部查看、手动添加或删除，提炼失败只会跳过本轮，不影响聊天

### 多角色群聊

- 从至少包含两个角色的分组创建群聊
- 创建时保存独立的成员快照；之后修改原分组不会影响已有群聊
- 在群聊中独立修改标题和成员
- 每条助手消息显示实际发言角色的名称和头像
- 发送用户消息后，根据角色名称、标签和最近发言情况选择发言角色
- 允许同一角色连续发言，但会降低连续选中的概率
- 点击“下一位”可自动选择或手动指定角色，在没有新用户消息时继续生成一条回复
- 请求中包含群聊成员资料，并要求模型只扮演本轮选中的角色

群聊发言者选择是本地启发式规则，不会为了选择发言者额外调用一次模型。

### 对话上下文

聊天页顶部的“对话设置”用于配置当前会话：

- **Persona**：用户身份、口吻或视角
- **Lorebook**：按关键词激活的世界信息
- **Prompt Preset**：System Prompt、Main Prompt、模型和生成参数覆盖
- **Author Note**：仅作用于当前会话的补充指令

点击“应用”保存当前配置；点击“清除”解除该会话的全部上下文绑定；关闭或取消弹窗不会保存修改。

“提示词检查器”可查看最终消息结构、估算 Token 数、已激活的 Lorebook 条目和历史裁剪情况。

聊天页顶部的 ❖ 打开“剧情回顾”：这是模型对较早剧情的唯一信息来源，可以手动改写；改写保存后自动整理会暂停，点“重新生成”会按当前对话重算并交还给自动整理。

对话本身也可以整理：📌 置顶让常用对话排在切换列表最前，分组名把同一篇章的对话归在一起（置顶与分组都只写各自的列，不会改动对话的更新时间）。

发送请求前，NativeTavern 会按设置里的 Context Length 估算总用量：减去回复预算和固定上下文后，如果历史消息仍然放不下，就从最早的轮次开始省略，始终保留最近的对话和当前这条消息；短对话不会被裁剪。该行为可在“设置 → 生成”中关闭。

### Prompt Studio

- 创建、编辑和删除 Persona
- 创建、启用、禁用和删除 Lorebook
- 管理 Lore Entry 的关键词、次级关键词、优先级、扫描深度和激活方式
- 创建 Prompt Preset，并覆盖模型、Temperature、Top P 和 Max Tokens

Lore Entry 支持：

- 普通关键词触发
- Constant 始终启用
- Selective 主关键词与次级关键词联合触发
- Priority 排序
- Depth 控制检索最近多少条聊天消息

### 模型服务

内置以下配置模板：

- OpenAI
- OpenRouter
- DeepSeek
- Claude（Anthropic Messages API）
- Gemini OpenAI compatibility API
- 自定义 OpenAI-compatible API
- Ollama
- LM Studio
- llama.cpp server

设置页支持：

- Base URL、API Key 和模型名称
- 获取远程或本地服务的模型列表
- 连接测试
- Temperature、Top P、Max Tokens 和 Context Length
- “请求超出上下文窗口时自动省略最早的轮次”开关，默认开启
- 扫描正在运行的 Ollama、LM Studio 和 llama.cpp 服务
- 中文与 English 界面切换

API Key 使用 Windows DPAPI 加密，通常只能由保存它的同一 Windows 用户解密。

### 本地 GGUF 模型

NativeTavern 可以扫描指定目录顶层的 `.gguf` 文件，并启动外部 `llama.cpp` server。

默认位置：

```text
NativeTavern/
├── llama.cpp/
│   └── llama-server.exe
└── LocalModels/
    └── Qwen3-8B-Q4_K_M.gguf
```

默认 llama.cpp 启动配置为：

- 地址：`127.0.0.1:8080`
- Context Size：8192
- GPU Layers：35
- Jinja 模板：启用
- 模型别名：`NativeTavern-Qwen3`

`llama-server.exe` 和 GGUF 模型不包含在 GitHub Release 中，需要用户自行准备，也可以在设置页改为其他路径。

### 本地知识库

- 导入 TXT、Markdown 和 PDF 文件
- 单个文件最大 20 MB
- 文档复制到应用数据目录后分块保存
- 启用或禁用单个文档
- 根据当前用户消息进行本地关键词检索，最多选取 4 个匹配片段

当前知识库使用本地关键词匹配，不是向量数据库或语义嵌入检索。

### 图片附件

- 支持 PNG、JPG/JPEG、WEBP 和 GIF
- 单张图片最大 10 MB
- 可通过按钮选择、拖入输入框或拖入应用窗口
- 附件保存在本地 `UserData/Attachments`
- 只有在设置中启用“图片上下文”后，图片才会编码并发送给模型

### 数据导出

- 角色页可将当前角色导出为 Character Card V3 JSON，也可选择 PNG 导出为图片角色卡
- PNG 导出沿用角色头像，并把角色卡同时写入 `ccv3` 和 `chara` 两个 tEXt 块；没有可用头像时自动生成纯色图片，旧头像里残留的卡片数据会被替换
- 导出的角色卡可重新导入 NativeTavern，也可用于兼容 V3 角色卡的工具
- 聊天页可将当前对话导出为便于阅读的 Markdown 或结构化 JSON
- JSON 导出保留中文原文，不再写成 `\uXXXX` 转义，方便直接查看和二次处理
- 角色卡 JSON 与 PNG 都会写出别名（`nickname`、`alt_names`），导入时同样读回
- 默认导出为“阅读版 HTML”：单文件、自带排版和打印样式，保留说话人、时间、收藏标记，`*动作*` 显示为斜体
- 导出的 HTML 不加载任何外部资源，模型或角色写进来的尖括号文字会被转义成普通文本，不会被当作网页代码执行
- 单聊与群聊导出都会保存时间信息；群聊会保留每条回复的实际发言角色
- 导出采用同目录临时文件替换，失败或取消时不会留下半写入文件
- 提示词工作室可将全部人设、世界书（含条目）、Prompt 预设和正则脚本导出为一个 JSON 资源包，用于换机迁移或分享配置
- 导入资源包只会新增内容，不会覆盖同名资源；重名时自动加上 `(2)`、`(3)` 后缀
- 导入同时接受 SillyTavern 世界书 JSON 和角色卡内嵌的世界书，字段按名称、关键词、内容、优先级、开关读取
- 缺少内容的人设、条目和无法编译的正则脚本会被跳过，界面会提示跳过数量；导入文件最大 20 MB

### 外观与文案脚本

- 浅色、深色和跟随系统三种外观，在“设置 → 界面 → 外观”中切换，无需重启
- 跟随系统时，Windows 深浅色变化会立即同步；窗口标题栏一起变色
- 整个界面共用一套调色板资源，新增颜色请使用方法中的语义画刷键名
- 正则脚本可按顺序对“模型回复”或“用户输入”执行查找替换，支持正则和纯文本两种匹配方式
- 脚本在流式输出时按自然段生效，保存后的消息与看到的内容一致
- 表达式无法编译时该脚本会被自动跳过，不影响聊天；编辑时可先用示例文本试用
- 在 📊 对话统计里发现角色口头禅后，点「→规则」直接生成一条纯文本替换脚本（把该说法从模型回复里去掉），下一条回复立即生效；同一个词已有规则时只提示，不会重复堆叠

### 桌面体验

- Windows 系统托盘
- 全局热键（设置 → 界面中开启）：「呼出 / 隐藏」热键在任意界面把窗口叫到前台或收起，「老板键」立即把窗口隐藏到托盘；热键可自定义，被其他程序占用时自动跳过
- 模型回复完成通知
- 主窗口淡入、轻微缩放和位移动画
- 遵循 Windows“在 Windows 中显示动画”的系统设置
- 中文和 English 界面
- 角色卡、图片和知识库文档拖放

### 插件中心

- 插件商城与已安装插件分栏
- 按名称、ID、作者或描述搜索
- 导入 `.ntplugin` 或 `.zip` 安装包，也可直接拖放安装
- 启用、停用、升级替换和卸载插件
- 商城下载强制使用 HTTPS，并校验 SHA-256、插件 ID 与版本
- 限制压缩包大小、文件数量和解压体积，拦截目录穿越、重复路径与符号链接
- 插件程序文件与持久数据分离，卸载不会删除插件数据

插件使用受控的声明式能力，不执行包内 DLL、脚本或可执行文件。项目附带“AI 动态角色状态”插件包源码：安装启用后，AI 会按对话、按角色维护不同的动态属性，并在消息头像下方提供状态弹窗。插件包及商城目录规范见 [`docs/plugin-packages.md`](docs/plugin-packages.md)。

## 快速开始

1. 从 [GitHub Releases](https://github.com/mlly-arcol/NativeTavern/releases) 下载 `NativeTavern.exe`。
2. 将 EXE 放进一个可写的独立文件夹。程序会在它旁边创建 `UserData`，建议不要直接放在临时目录。
3. 启动程序并打开“设置”。
4. 选择 Provider，填写 Base URL、API Key（如需要）和模型名称。
5. 点击“测试连接”，成功后点击“保存”。
6. 前往“角色”创建或导入角色，然后点击“开始对话”。

使用本地服务时，可以先启动 Ollama、LM Studio 或 llama.cpp，再在设置页点击“扫描本地服务”；也可以选择 GGUF 文件后由 NativeTavern 启动 llama.cpp。

## 创建群聊

1. 在“角色”页面点击“创建分组”。
2. 输入分组名称，并勾选至少两个角色。
3. 保存后，在分组卡片上点击“群聊”。
4. 输入消息，系统会自动选择一个角色回复。
5. 使用聊天页的“成员”修改群聊标题或成员，使用“下一位”继续角色间的对话。

## 数据与备份

所有主要数据保存在 EXE 所在目录旁的 `UserData`：

```text
UserData/
├── Data/
│   └── NativeTavern.db
├── Avatars/
├── Attachments/
├── Documents/
├── Plugins/
├── PluginData/
├── Cache/
└── Logs/
    └── NativeTavern.log
```

- SQLite 数据库保存角色、分组、会话、消息、Swipe、Persona、Lorebook、Preset 和设置。
- 头像、附件及知识库原始文件以普通文件形式保存。
- 备份时请先退出 NativeTavern，然后复制整个 `UserData` 文件夹。
- 不要只复制数据库，否则头像和附件可能缺失。
- 从旧版本迁移且当前目录还没有数据库时，程序会尝试从旧的 `%LOCALAPPDATA%\NativeTavern` 或 Codex 沙盒数据目录复制旧数据。

设置页提供“一键创建备份”和“恢复备份”：

- 备份文件为 ZIP，包含数据库、头像、附件、知识库、插件和插件数据。
- 恢复前会校验备份数据库完整性。
- 恢复前自动创建一份当前数据的安全备份。
- 恢复完成后应用会关闭，需要手动重新启动。

在源码仓库中，从根目录或 `publish` 目录启动都会共用项目根目录的同一份 `UserData`，避免产生重复数据目录。

## 隐私设置

下列内容默认不会自动加入模型请求，必须在设置页明确启用：

- 角色卡上下文
- 本地知识库匹配片段
- 图片附件数据
- 角色记忆（启用后才会自动提炼并随请求发送）

Persona、Lorebook、Prompt Preset 和 Author Note 属于用户主动绑定到当前会话的提示词资源。使用在线 Provider 时，实际加入请求的内容会发送给对应服务商；发送前可使用“提示词检查器”查看文本结构。

## 快捷键

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl+N` | 新建对话 |
| `Ctrl+Shift+P` | 打开提示词检查器 |
| `Ctrl+,` | 打开设置 |
| `Enter` | 发送消息；回复仍在生成时进入排队 |
| `Shift+Enter` | 输入换行 |
| `Ctrl+Enter` | 重新生成最后一条助手消息 |
| `Esc` | 停止当前生成 |

快捷键在 NativeTavern 窗口获得焦点时生效，不是系统级全局热键。

## 系统要求

使用 Release 中的自包含版本：

- Windows x64
- 无需单独安装 .NET Desktop Runtime
- 在线模型需要网络连接和相应服务凭据
- 本地模型的内存、显存和磁盘要求取决于所选 GGUF 模型

从源码构建：

- Windows
- .NET 10 SDK
- Git

## 从源码构建

```powershell
git clone https://github.com/mlly-arcol/NativeTavern.git
cd NativeTavern
dotnet restore
dotnet build NativeTavern.csproj -c Release
```

运行测试：

```powershell
dotnet test Tests\NativeTavern.Tests\NativeTavern.Tests.csproj
```

生成 Windows x64 自包含单文件版本：

```powershell
dotnet publish NativeTavern.csproj -c Release -r win-x64 --self-contained true -o publish
```

发布完成后，构建目标会自动把 `publish/NativeTavern.exe` 同步为项目根目录的 `NativeTavern.exe`。该大型构建产物已被 Git 忽略，正式二进制文件通过 GitHub Releases 分发。

## 技术栈

- C# / .NET 10
- WPF
- CommunityToolkit.Mvvm
- SQLite + Dapper
- Microsoft.Extensions.DependencyInjection / Http / Logging
- Windows DPAPI
- PdfPig

核心分层：

```text
Views → ViewModels → Services → Repositories / Providers
```

## 当前限制

- 仅支持 Windows x64，没有 Web、Linux、macOS 或移动版本。
- 聊天消息支持常用 Markdown（标题、粗体、斜体、列表、引用、链接、行内代码与代码块）；暂不包含代码语法高亮、LaTeX、HTML 和远程图片渲染。
- 当前没有云同步或多账户。
- 插件中心支持受控的声明式能力；任意代码加载和通用运行时 API 尚未开放。
- 知识库是关键词检索，不是向量 RAG。
- Release 是便携式单文件程序，没有安装器和在线自动更新器。
- 本地发布时自动替换根目录 EXE 是开发构建步骤，不是客户端在线更新功能。

- 修复顶部弹出面板（剧情回顾、对话统计、搜索结果）靠右时被窗口边缘裁切的问题
- 跨对话搜索框补上占位提示，未输入时也能看出用途
- 统计与搜索结果在无障碍树里显示为可读文本，不再是内部类名
- 未发送的输入（含待发送图片）按对话分别保留，切换对话自动带走各自的草稿，发送或删除后清空
- 草稿写入 SQLite 的 `ComposerDrafts` 表，关闭程序再打开仍会回到原来的对话；删除对话时草稿一并级联清除
- 写盘做了防抖：停止输入约 0.8 秒才落库一次，切换/发送/删除时立即落库，不会每个按键都写数据库
- 修复切换到长对话时草稿被覆盖的问题：加载期间新敲的内容现在优先于切换前的草稿
- 草稿规则抽成 `DraftStore` 与 `ComposerDraftRepository`，切换/加载/发送/删除/重启的行为由 16 项测试覆盖（全套 176 项通过）
- 新增排队发送：回复还在生成时按 Enter 不会丢输入，消息排队等本轮结束后自动发出，可按对话分别 ✕ 取消或清空
- 生成中的输入不再被“禁用发送按钮”挡回去，队列按对话归属，切到别的对话不会误发
- 流式回调改用统一的 UI 调度入口，没有窗口也能跑通整段对话流程测试（新增 9 项，全套 185 项通过）
- 新增“续写”：让角色接着最后一条回复往下写，写出的内容拼在原句后面，原版本作为旧候选保留，可左右翻回
- 续写请求会把已写出的正文作为最后一轮助手消息带上，并附一句“只写后续、不要重复”的指令；空回复和更早的回复不会被误续写（新增 3 项，全套 188 项通过）
- 打开对话改为整段批量读取：候选回复与图片附件各一次查询，缺失的首个候选用一条 `INSERT … SELECT` 补齐，不再逐条消息往返数据库
- 实测 300 条消息的对话，读取部分从约 380ms 降到约 9ms（同一台机器、同一份测试库，重复三次结果稳定；批量读取与逐条读取结果一致的测试 2 项，全套 190 项通过）
- 对话统计新增“角色反复用到的说法”：本地找出最近回复里出现三次以上的短语，帮作者看见模型的口头禅，不需要额外调用模型
- 口头禅扫描放在 UI 线程之外，面板先出数字后补短语；最坏情况（120 条 × 4000 字）实测约 86ms，常规长度约 20–50ms
- 测试改为串行运行：Microsoft.Data.Sqlite 只能整进程清池才能释放临时库文件，并行时一个测试类的清理会打断另一个类的连接（改前偶发失败 2 次，改后连续三次全绿，200 项约 12 秒）
- 口头禅标签上加了「→规则」：一键生成作用于模型回复的纯文本替换脚本，把该说法直接删掉，下一条回复就生效；重复点击只会提示，不会堆同一条规则
- 新增依赖注册自检（8 个视图模型的构造参数逐一比对容器），漏注册的服务在测试里就会失败，而不是等读者打开对话时才崩（全套 210 项通过）

## 项目定位

NativeTavern 不是 SillyTavern 的完整复刻，也不追求覆盖所有扩展能力。它专注于一个范围更小的目标：提供干净、原生、可离线保存数据，并适合个人长期使用的 Windows 角色聊天工作区。

2.0 是这一目标下的功能完整版本。插件代码执行、云同步、多账户和跨平台客户端不属于当前核心范围。
